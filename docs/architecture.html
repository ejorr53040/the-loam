The Loam

Members of a closed group lend idle CPU and GPU time to one pool on a LAN. The Loam is its own system. It drives cirrocumulus (dashed boxes), which stays untouched on a local socket. Click any box, then follow a trace.

    What the pool needs to work

    Sorted by when it bites. The build order in the repo's design doc follows the first column.

    Needed first

    • Surface client with a contract test against the real cirrocumulus socket.
    • Pool identity: CA, one-time join tokens, member and node credentials.
    • Worker with owner policy, a RAM budget, and a loam- name prefix.
    • Registry from heartbeats, and a multi-node loam top.
    • Scheduler with leases, retries and backoff.
    • Ingress with a route cache that survives a server stop.
    • Tasks that are idempotent, with a timeout and a size cap.
    • Ledger of usage and security events.

    Makes it pleasant

    • Exit code and file copy-out in cirrocumulus, as single-machine features.
    • A chunked content store, so tasks can move more than a small payload.
    • GPU batch on the host, outside microVMs, when the owner's card is free.
    • Server replication, and quotas that read the ledger.
    • Real input-idle detection, if cgroup weights are not enough.

    Not in v1

    • Anything cluster-shaped inside cirrocumulus.
    • Distributed training (research track; only a placement-group field is reserved).
    • GPU inside a microVM.
    • Windows, macOS or non-KVM donors.
    • Machines across home networks, relays and NAT traversal.
    • Credits, tokens, payments, or strangers on the public internet.
